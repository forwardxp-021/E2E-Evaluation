# F1 — Controller与model传递审查 v1

## 1. 【源码事实】数据路径及重要控制边界

`tsb_coast_p1r_planner.reference_profile`每次以current speed为未来速度首值，只积分当前时刻之后的冻结C2片段；路线位姿依该未来距离生成，planner states[0]再替换成实际ego。没有保存最初全局速度轨迹作为纵向误差目标。

`CoastC2PlannerV1.compute_planner_trajectory`在elapsed<1.1秒时让两臂整个未来参考相同，使用Baseline；不是提前给Treatment第一脚参考。1.1秒才切换Treatment未来参考。Treatment[2.1,3.9)的adapter绕过纵向LQR/stop solver，最终u=0；因此不能在第二脚前1秒用LQR提前制动。横向跟踪和官方model传播始终继续。

官方LQR `_compute_reference_velocity_and_curvature_profile`读取轨迹位姿，经`tracker_utils`对位移进行含jerk正则的速度/加速度拟合，再取t+H的速度；H=10×0.1=1秒。生产cfg q_long=10、r_long=1、jerk_penalty=0.0001。纵向控制不是a_ref直接通道。

## 2. 【数学推导】这个LQR的系数作用于速度误差

一维one-step LQR给出：

`u = [Q H / (R + Q H²)] × (v_ref,fit(t+H) − vx_current)`。

当前配置的系数为10/11 s⁻¹。它不是“参考加速度到实际加速度”的固定增益：参考来自未来位姿拟合，planner每步重锚速度，common gate/coast gate又随时段切换。

【解释性近似，非新运行】忽略位姿拟合误差和初始小扰动时，一段只剩ℓ秒的制动参考，使重锚后的未来速度误差近似−Aℓ。因此请求会随ℓ缩短而下降，而不是持续−A，也不会追赶已经少减掉的历史速度。对本来冻结的A=1.305和ℓ=1.0,0.9,…,0.1秒，十个区间的近似负请求积分是：

`(10/11) × 1.305 × 0.1 × Σ(1.0,…,0.1) = 0.6525 m/s`。

【实测对照】两脚真实负请求积分分别0.652504590、0.652471162 m/s。近似式与事实吻合，支持“剩余短参考+重锚+预瞄”的机制解释；它没有拟合一个通用线性增益，也不能用于反推或推荐新幅值。历史请求的详细斜坡不被该近似完全解释。

Baseline在自己的参考制动窗开始前[1.1,2.1)已经收到0.659069763 m/s负请求积分；主窗[2.1,3.9)又收到1.831552179 m/s。较长参考允许请求维持及模型响应积累。Treatment每脚短窗只有约0.6525；第一脚没有独立提前预瞄时段，第二脚的提前时段被零请求窗占据。Baseline/Treatment门控的时间结构也不是一个相同线性滤波器作用在两个完整矩形波形上。

## 3. 【源码事实+数学推导】官方model滤波

`a_next = (2/3)a_before + (1/3)u`，`vx_next = vx_before + 0.1 a_next`。

dt=0.1秒，tau=0.2秒。model没有分别可验证的驱动/制动扭矩、阻力/坡度系统；u=0是抽象零纵向请求，非现实零踏板证明。

对N个既有区间求和可得精确恒等式：

`0.1 Σ a_next = 0.1 Σ u + 0.2(a_initial − a_final)`。

它说明滤波会降低短脉冲峰值、把减速挪到后续窗口；在足够完整的有限窗内，净有符号面积只多出端点项，不能简单说“滤波吃掉了约一半的总剂量”。

| 已有区间求和 | Baseline | Treatment | 单位 |
|---|---:|---:|---|
| 最终请求有符号积分 | −2.490114234 | −1.304647887 | m/s |
| model实际有符号积分 | −2.464467329 | −1.278947783 | m/s |
| filter端点项 | +0.025646905 | +0.025700104 | m/s |
| 恒等式残差 | −7.98e−17 | +1.11e−16 | m/s |

两臂model净速度变化的差1.185519546 m/s，分解为请求有符号积分差1.185466348，加filter端点项差0.000053198 m/s。主要的整体降速差已在请求层存在。

## 4. 【实测】峰值不足的两层来源

Treatment请求峰值约1.1685/1.1683 m/s²，但不是能维持1秒的矩形；到参考窗末尾已接近0。模型滤波不能在这个下降请求中积累到相同峰值，所以模型实际峰值只有0.76557/0.76518；冻结速度代理约0.75690/0.75658。两脚参考幅值与实际峰值的比值只能描述本次脉冲，不是系统通用增益。

滑行残余从a(2.1)=−0.329421634衰减到a(3.9)=−0.000222900；18次请求0，符合同一滤波式。3.9秒LQR恢复后请求−1.168298181。零请求gate没有失效，且零请求期间并未清空model残余状态。

## 5. 不能声称的因果结论

未单独关闭jerk拟合、改变预瞄或滤波来重演；未算新的有利测量算子；未调用LQR/model重构反事实。因此无法用一个SESSION精确分摊“多少百分比由预瞄、重锚、姿态拟合或滤波造成”。可以确认的是：请求波形本身面积不足、实际model方程吻合、测量代理不是峰值不足的唯一解释。

`F1_Paired_Speed_Difference_v1.csv`中`inferred_LQR_reference_vx`由既有u、vx及上述固定系数代数反推，只在非COAST区间填写；它不是历史记录器实测的v_ref，不用于选参数或重新判定。
