## 有限路线

`P0构念/解析可行性（本包） → Owner review → P1有限Development（另行授权） → Owner review → P2独立冻结资格（另行授权） → Owner独立Primary修约/训练与数据门/冻结 → 是否进入BDD`。

阶段不能打包默许；P1通过不自动运行P2，P2通过也不自动训练、修改Primary或执行V/C。

## P1建议：仅一个科学候选C2

| 约束 | 建议硬上限 / 前瞻规则 |
|---|---|
| 科学候选 | 仅C2；C1留在解析对照，不花rollout预算；无参数网格、无按场景参数 |
| 实现版本 | P1科学运行前最多2个零运行代码迭代，冻结单一版本/参数/平滑方案/阈值。若仍不ready，停止；不能看曲线后做第二科学版本 |
| Development身份 | 3个B-development SESSION各1对；先按元数据、route有限需求、初速≥5m/s建议域和暴露规则一次性绑定。不能根据旧曲线强弱/成功率挑身份，不在P0构建名单 |
| 首次arms | 3×2=6，预定顺序逐pair执行，遇明确科学FAIL立即停，未运行成员保留NOT_RUN，不称6arm完整 |
| 技术retry | 每arm最多一次，且总额最多2次；同身份/同科学版本、新namespace，全部失败记录保留；需授权明确允许，不是当前许可 |
| 累计attempt ceiling | 8（含失败/重试；超时也算）；不补场景、不替代成员、不扩样 |
| 时间/资源 | CPU科学运行≤3小时累计、单arm≤20分钟、实施/复核≤2个工作日、GPU=0；本机CPU实际吞吐未测，不承诺时限内一定完成 |
| 判断材料 | 真实机制/测量/F_match/官方安全及技术工件；H向量、BDD、MMD、RBR推理均禁用 |

3个SESSION只证明有限Development可运行性，不是可靠性估计或资格样本。若3/3通过且无测量不稳定，提交Owner决定是否值得P2；不是宣布新基准PASS。P1数据全部标E2、不得洗成P2。

## 技术与科学失败

- 技术失败：runner异常、native-route不可解析、callback/serializer缺失、工件持久化损坏。只允许修与科学计算无关的问题，前瞻分类、hash差异审计和明确授权后重试；不能借技术修复改参考、控制器、阈值或roster。需要超出已批allowlist的修复时立即停止等待Owner。
- 科学失败：两脚合并、near-zero core不足、正恢复超限、测量由真实动态造成不稳定、low-speed/endstop、F_match不合格或官方安全失败。不得技术重试或换SESSION救结果；P1即停止，归档全部已尝试成员及未运行分母。
- 只要需要正加速、放宽滑行语义、改控制器或新参数才能通过，判当前固定平台/预算设计不成立，停止；不能把其包装成工程优化继续跑。

## P2建议（未授权）

仅在P1+Owner审查后，冻结全新资格合同、20个独立SESSION和40arm完整名单，与P1和旧B1分离。不得看资格结果改阈值或补场景。资格标准拟为所有20对通过五层合同；20不是Primary m20容量证明，也不是总体可靠性保证。

最多40首次attempt+2全局技术retry=42；每arm最多一次retry，同身份；首次科学FAIL立即停止并报告固定20分母的失败/未运行，不宣布全PASS。资源建议≤16 CPU小时、单arm≤20分钟、≤5工作日、GPU=0。技术retry仍须独立授权写明；若预检独立SESSION容量不足，不开跑、不放宽身份或按已知成功者替换。此预算是cost ceiling，不是统计power论证。

## 收缩路径

P0当前无运动学矛盾，但闭环仍未知。若P1在固定C2下不成立，结论为“当前冻结LQR/预算下未建立自然语义双制动构念”；保留旧B1正恢复基准、方法学分层验证、强人工H和阴性工程/科学证据。论文主张收缩为已验证构念/Level1及数据合同成果；如仍希望Coast，必须另立有理由的新Owner决策，不将新循环视作本计划延长。不为了RBR胜出而回退、换题或不断调参数。
